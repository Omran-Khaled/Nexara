# تقرير المرحلة P13 — هندسة الأداء

**المشروع:** Nexara Digital Library  
**المرحلة:** P13 — Performance Engineering  
**تاريخ القياس:** 18 أغسطس 2026  
**حالة بوابة الأداء:** **PASS**

> طبقت P13 تحسيناً واحداً فقط: **تقسيم حزمة الواجهة حسب العرض والحوارات**. جاء القرار بعد قياس حزمة أولية واحدة بحجم `898,348` بايت خام و`251,164` بايت مضغوطاً. لم تطبق فهارس أو projections أو تخزين مؤقت أو debounce أو pagination إضافية أو تحسين صور لمجرد أفضل ممارسة، لأن القياسات لم تثبت عنق زجاجة في تلك المسارات.

## 1. منهجية القياس

شغّل القياس بناء الإنتاج الفعلي (`dist/server.cjs`) ضد `MongoMemoryReplSet` مؤقتة، مع كتالوج المشروع وكتاب قارئ كبير مكوّن من 400 فصل، وهو نفس نمط الضغط المعتمد في اختبار القارئ P5. استعملت الأداة `scripts/p13-measure-baseline.ts` طلبات HTTP محلية متتابعة، 30 عينة لكل مسار API واستعلام MongoDB، وChromium headless عبر بروتوكول DevTools لالتقاط TTFB وFCP وزمن تنفيذ JavaScript والرسم والذاكرة.

> هذه الأرقام **قياسات محلية قابلة لإعادة التشغيل**، لا ادعاء عن إنتاج موزع جغرافياً أو بيانات مستخدمين حية. لا يجوز تحويلها إلى SLA أو توقع مباشر لأجهزة وشبكات العملاء المختلفة.

| البعد | أسلوب القياس | نطاق البيانات |
|---|---|---|
| بدء الخادم | من spawn عملية الإنتاج إلى `/api/health/live` | MongoDB مؤقتة وتهيئة الإنتاج المحلية |
| API وTTFB | 30 طلب HTTP متتابع | الكتالوج، فصل من كتاب كبير، وفهرس الكتالوج |
| MongoDB | 30 استعلام `MongoBookRepository.search` | 11 كتاباً في كتالوج المشروع |
| القارئ | مسار `/books/p13-long-arabic-book/read` | 400 فصل عربي/إنكليزي، 1,040 حرفاً عربياً في الفصل |
| الواجهة | Chromium headless | FCP، التنفيذ، الرسم، heap، ومهام المتصفح |
| الحزمة والصور | `dist/assets` و`public/covers` | ملفات بناء الإنتاج الفعلية |

تظهر البيانات أن **المسار الخلفي لم يكن عنق الزجاجة** في بيئة القياس: p95 للبحث في MongoDB والكتالوج ظلا ضمن عشرات الملي ثانية، والقارئ يطلب الفصل على حدة بدلاً من دفع نص 400 فصل في استجابة الكتالوج. بالمقابل، كانت حزمة JavaScript الأولية ملفاً واحداً كبيراً وأدخلت واجهات القارئ والإدارة والمجتمع والحوارات في تحميل البداية، رغم أن معظمها لا يستخدم في الزيارة الأولى.

## 3. التحسين المطبق ومبرره

حُوِّلت العروض غير الأولية والحوارات الثقيلة إلى `React.lazy`، مع حد `Suspense` وحالات تركيب مشروطة. تشمل الوحدات المنفصلة القارئ، لوحة الإدارة، المجتمع، المكتبة الشخصية، البحث الخارجي، تفاصيل الكتاب والمؤلف، لوحة الأوامر، الاستوديو، والحوارات. لا يتم طلب هذه الوحدات قبل أن يفتح المستخدم العرض أو الحوار المرتبط بها.

| القرار | الدليل قبل التعديل | التنفيذ |
|---|---|---|
| Code splitting للعروض | ملف أولي واحد: 898,348 bytes خاماً و251,164 gzip | `React.lazy` للوحدات غير الأولية في `src/App.tsx` |
| Code splitting للحوارات | الحوارات كانت مركبة عالمياً حتى عند إغلاقها | تركيب مشروط وفق حالة المتجر مع `Suspense` |
| إبقاء التحميل الأولي قابلاً للإتاحة | التحميل الكسول قد يترك فجوة مرئية | fallback بنص حالة وصولي عربي/إنكليزي |

## 4. إعادة القياس بعد التحسين

| المؤشر | قبل | بعد | التغير |
|---|---:|---:|---:|
| الحزمة الأولية الخام | 898,348 bytes | 662,503 bytes | **−235,845 bytes (−26.25%)** |
| الحزمة الأولية gzip | 251,164 bytes | 193,682 bytes | **−57,482 bytes (−22.89%)** |
| Library FCP | 472 ms | 144 ms | **−328 ms (−69.49%)** |
| Library script duration | 149.538 ms | 108.338 ms | **−41.200 ms (−27.55%)** |
| Library layout duration | 273.538 ms | 187.084 ms | **−86.454 ms (−31.61%)** |
| Library task duration | 562.199 ms | 407.153 ms | **−155.046 ms (−27.58%)** |
| Reader FCP | 76 ms | 56 ms | **−20 ms (−26.32%)** |

ظهر تقسيم الوحدات في بناء الإنتاج كملفات مستقلة، ومنها `ReadingEngine` و`AdminDashboard` و`CommunityView` و`MyLibraryView` و`BookDetailModal`. أضيفت بوابة `test:p13` لحراسة الحزمة الأولية عند حدين مشتقين من هذه النتيجة: 700 KB خاماً و210 KB gzip، وللتحقق من استمرار الوحدات الثقيلة كـ chunks منفصلة.

لوحظت ضوضاء قياس طبيعية في بدء الخادم وp95 لخلفية MongoDB/API بين التشغيلين المحليين؛ لم تنسب P13 هذا التغير إلى code splitting، ولم تستخدمه مبرراً لتحسين إضافي. زاد heap القارئ في قراءة ثانية بمقدار 17.07% مع بقاء FCP أسرع؛ لذلك لا توجد مطالبة بتحسين ذاكرة القارئ قبل الحصول على لقطة استخدام طويلة ومتعددة الفصول من بيئة حية.

## 5. تحسينات لم تطبق عمداً

| التحسين المحتمل | القرار | سبب عدم التطبيق في P13 |
|---|---|---|
| MongoDB projection أو index جديد | لم يطبق | p95 الاستعلام 22.911 ms في خط الأساس؛ لا دليل على مسار بطيء أو فهرس مفقود. |
| API pagination إضافية | لم تطبق | `/api/books` يستخدم page/limit بالفعل، واستجابة الكتاب الكبير لا تحمل متن الفصول. |
| API caching أو request deduplication | لم يطبق | لم يظهر القياس طلبات متكررة متزامنة أو كمون API يبرر تعقيد cache وصلاحيته. |
| Debounced catalog search | لم يطبق | بيانات القياس لم تتضمن كتابة حية بكتالوج كبير أو طلباً خارجياً في كل ضغطة؛ لا يصح افتراض المشكلة. |
| Prefetching | لم يطبق | قد ينقل الكلفة إلى المستخدمين الذين لا يفتحون الوجهة؛ لا يوجد قياس تتابع تنقل حقيقي يبرره. |
| Image transformation أو CDN policy | لم تطبق | الأصول المحلية المقاسة 859 bytes فقط؛ أغلفة الكتالوج خارجية وتحتاج telemetry إنتاجية قبل تغيير سياسة الصور. |
| إخلاء cache القارئ | لم يطبق | مسار الفصل مفصول وخفيف، ولا توجد عينة طويلة تثبت أن heap يرتفع خطياً عبر مئات الفصول. |
