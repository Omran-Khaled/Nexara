# تقرير المرحلة P9 — التحصين الأمني ومراجعة OWASP

**المشروع:** Nexara Digital Library  
**المرحلة:** P9 — Security Hardening  
**المراجع:** Manus AI  
**تاريخ التحقق:** 18 أغسطس 2026  
**قرار البوابة:** **PASS — لا توجد ثغرة High أو Critical معروفة في المسارات الأساسية التي شملها النطاق.**

> هذا القرار هو نتيجة مراجعة بيضاء/رمادية للصورة البرمجية المتاحة، وفحص بنائي واختبارات محلية موجهة للمخاطر. لا يشكل ضماناً مطلقاً ضد ثغرات مستقبلية أو ثغرات في البنية السحابية أو إعدادات النشر غير المتاحة في بيئة المراجعة.

## 1. نطاق المراجعة ومنهجيتها

شملت المراجعة المسارات الأساسية في واجهة Express، والهوية والتفويض، وعمليات القراءة والتنزيل، ورفع الكتب وتخزينها، وتكامل مصادر الاستكشاف الخارجية، وواجهة React. وقد تمت مراجعة المدخلات والمسارات والأجسام الثنائية وسلاسل إعادة التوجيه، ثم تطبيق ضوابط دفاعية وإضافة اختبار P9 مستقل.

اعتمدت ضوابط الرفع على مبدأ **الدفاع متعدد الطبقات**؛ إذ تنص إرشادات OWASP على عدم الوثوق بترويسة `Content-Type` وحدها، وعلى الجمع بين قوائم السماح، والتحقق من البصمة، وحدود الحجم، والتخزين المعزول، وفحص البرمجيات الخبيثة عند توافره.[1] كما تم التحقق من ملكية الكائنات وصلاحيات كل عملية على الخادم، بما يتماشى مع توصية OWASP بإجراء تفويض على مستوى الكائن في كل دالة تتعامل مع معرّف يرسله العميل.[2]

| مجال التحقق | المنهج المطبق | النتيجة |
|---|---|---|
| مراجعة ساكنة | فحص مسارات API، معالجات الإدخال، الوصول إلى الملفات، الاستدعاءات الشبكية، ومصارف XSS | مكتمل |
| مراجعة ديناميكية | `tests/p9.security-hardening.test.ts` لحالات الرفض والإتاحة الآمنة | ناجح |
| انحدار وظيفي | اختبارات P0–P8 الأساسية، مع تركيز P4/P6/P7/P8 | ناجح |
| بناء إنتاج | `npm run build` مع فحص المخرجات | ناجح |
| اعتماديات وقت التشغيل | `npm audit --omit=dev` | 0 Critical، 0 High |

## 2. التغييرات المنفذة

تم فصل سياسة أمان الرفع في وحدة مركزية وربطها بالخادم الفعلي وإعداداته. وأصبحت خدمة الكتب تتحقق من المحتوى قبل الكتابة إلى التخزين، ولا تحفظ السجل إلا بعد مطابقة الحجم وSHA-256 بين الذاكرة وموفر التخزين. كذلك لا يظهر مفتاح التخزين الداخلي في استجابة رفع الملف.

| الملف | التغيير الأمني الجوهري |
|---|---|
| `server/security/FileUploadSecurity.ts` | قائمة MIME مسموحة، فحص بصمة وبنية PDF/EPUB، UTF-8 للنصوص، حظر HTML النشط، فحص اسم الملف والامتداد، حد الحجم، وتكامل `clamdscan` اختياري يفشل بإغلاق عند طلبه. |
| `server/services/BookFileService.ts` | فحص الملف قبل التخزين، تحقق SHA-256 والحجم بعد التخزين، تقييد `sourceUrl` إلى HTTPS بلا بيانات اعتماد، وإبطال grant بعد استعماله. |
| `server/controllers/BookFileController.ts` | قبول اسم ملف مضبوط فقط، رؤوس تنزيل/قراءة مقيدة، ومنع العرض المضمّن لـ HTML عبر إرساله كمرفق ثنائي مع CSP sandbox. |
| `server/middleware/security.ts` | رؤوس حماية إضافية، CORS بقائمة أصول دقيقة، حارس CSRF يعتمد Origin وFetch Metadata، وحدود معدلات عامة وحساسة محدودة الذاكرة. |
| `server/middleware/errorHandler.ts` | منع إرسال تفاصيل المزود أو مكدس الاستثناء إلى العميل؛ تفاصيل الحقول مقتصرة على أخطاء التحقق. |
| `server/middleware/requestReliability.ts` | حذف query string من سجل الطلبات كي لا تسجل رموز الوصول المؤقتة. |
| `server/discovery/GutenbergDownloadService.ts` و`providerHttp.ts` | إعادة توجيه يدوية، بحد أقصى خمس محاولات انتقال، مع السماح فقط بـ HTTPS على نطاق Gutenberg قبل كل قفزة. |
| `server/config/env.ts` و`.env.example` | إعدادات صريحة لحد الرفع والماسح؛ وإلزام `NEXARA_CORS_ORIGINS` في الإنتاج. |
| `tests/p9.security-hardening.test.ts` | بوابة P9 تغطي الرفع، مكافحة البرمجيات الخبيثة، CORS، CSRF، SSRF، الرؤوس، grants، والحدود المعدلية. |

## 3. نتائج مراجعة المخاطر

| الفئة | الضابط أو نتيجة المراجعة | الحالة |
|---|---|---|
| Injection | المعرّفات تمر عبر `parseId`، ومدخلات JSON مقيدة، واستعلامات Mongo تستخدم حقولاً مقيّدة وليست عوامل يرسلها العميل. | **مقبول** |
| XSS | لا توجد مصارف `dangerouslySetInnerHTML` أو `eval` أو `document.write` في المصدر المفحوص؛ HTML المرفوع يرفض المحتوى النشط ولا يعرض داخل نفس الأصل. | **مقبول** |
| CSRF | المصادقة الأساسية Bearer وليست Cookie ambient؛ طلبات التغيير تتحقق من Origin عندما يوجد، وترفض `Sec-Fetch-Site: cross-site` غير المصرح. | **مقبول** |
| CORS | لا توجد wildcard أو credentials؛ الأصل يطبع ويطابق قائمة سماح، والإنتاج يرفض التشغيل بلا قائمة أصول. | **مقبول** |
| SSRF | نقاط الاستكشاف ثابتة، ومعرّف Gutenberg رقمي؛ تنزيل المحتوى يستخدم HTTPS ومضيف Gutenberg فقط، وإعادة التوجيه يدوية ومقيدة. | **مقبول** |
| IDOR / BOLA | الموارد الخاصة تربط `userId` بـ principal على الخادم؛ الاختبارات السابقة لـP8 وحالة P9 تؤكد الرفض عند اختلاف المالك أو grant. | **مقبول** |
| Broken access control | صلاحيات `FILE_WRITE` و`RIGHTS_MANAGE` و`AUDIT_READ` و`ROLE_MANAGE` مفروضة في المعالجات؛ المستخدم لا يختار دوره من body. | **مقبول** |
| Prototype pollution | لا يوجد دمج عميق لحمولات غير موثوقة في النطاق المفحوص؛ الكيانات تنشأ من validators وقيم محددة. | **مقبول** |
| Unsafe redirects | لا توجد redirects للعميل تعتمد على مدخل حر؛ إعادة توجيه Gutenberg مقيدة يدوياً. | **مقبول** |
| Path traversal | مفاتيح التخزين تخضع لـ allowlist وتمنع `..`، واسم الملف لا يستعمل في مسار التخزين؛ المسار الداخلي مولد من UUID. | **مقبول** |
| Content-type confusion | MIME على allowlist، مع فحص بصمة/بنية مستقلة؛ `nosniff` مفعل. | **مقبول** |
| Oversized payloads | JSON مقيد إلى 1 MiB، والملفات إلى حد مضبوط قابل للتهيئة لا يتجاوز 100 MiB، وEPUB يفرض سقف تمدد مفكوك 512 MiB ونسبة ضغط 100:1. | **مقبول** |
| Rate limiting / brute force | حد عام لكل IP/فئة مسار وحد أشد لمسارات الرفع والتنزيل والحساسة، مع `429` و`Retry-After`. | **مقبول محلياً** |
| Secret exposure | نموذج البيئة يستعمل مفاتيح بديلة؛ فحص حزمة الإنتاج لم يجد نمط service role أو مفاتيح AWS خاصة؛ مفاتيح التخزين لا تعاد للعميل. | **مقبول** |
| Error leakage | العميل لا يتلقى `cause` أو stack أو تفاصيل مزود؛ يسجل الخادم التشخيص داخلياً مع `requestId`. | **مقبول** |
| Security headers | `HSTS` في الإنتاج، CSP، `X-Frame-Options: DENY`، `nosniff`، `Referrer-Policy`، Permissions Policy، COOP/CORP، وOrigin-Agent-Cluster. | **مقبول** |

## 4. أمن رفع الملفات

يقبل النظام أربعة تنسيقات فقط: PDF وEPUB وTXT وHTML. لا يكفي نوع MIME المعلن، إذ يقارن النظام النوع بالصيغة المختارة ثم يتحقق من محتوى فعلي. تُفحص ملفات PDF ببادئة `%PDF-` وتذييل `%%EOF`. وتخضع EPUB لتحليل ZIP مبسط لكن مقيد: مدخل `mimetype` غير مضغوط في أول موضع، ودليل مركزي صحيح، وحدود للعدد والحجم ونسبة الضغط، ومنع لمسارات `..` أو المطلقة داخل الأرشيف. هذا يخفف مخاطر الحاويات المزيفة وقنابل الضغط، وهي من المخاطر التي تشير إليها OWASP صراحةً عند فك الملفات أو معالجتها.[1]

| ضابط الرفع | التنفيذ | النتيجة |
|---|---|---|
| MIME allowlist | PDF وEPUB وTXT وHTML فقط | مفعّل |
| Magic bytes / بنية | PDF وEPUB؛ UTF-8 وقيود التحكم للنص؛ بنية HTML | مفعّل |
| الامتداد واسم الملف | مطابقة الامتداد للصيغة، 255 حرفاً كحد أقصى، منع المسارات و`..` وNUL | مفعّل |
| الحجم | `BOOK_STORAGE_MAX_BYTES`، حد أقصى 100 MiB؛ JSON 1 MiB | مفعّل |
| Checksum | SHA-256 قبل التخزين والتحقق من الحجم والـchecksum بعده | مفعّل |
| Content parser | محلل EPUB/ZIP مقيد، وفحص PDF/نص/HTML حسب النوع | مفعّل |
| تخزين آمن | مفتاح مولد بالتطبيق، لا اسم مستخدم، وعزل عن web root في الإنتاج عبر S3-compatible | مفعّل |
| Malware scanning | `BOOK_MALWARE_SCANNER=clamdscan` و`BOOK_REQUIRE_MALWARE_SCAN=true`؛ يرفض الرفع إذا كان الفحص إلزامياً وغير متاح | **مهيأ، يتطلب تشغيل ClamAV في النشر** |
| تسليم المحتوى | grant قصير العمر أحادي الاستخدام؛ HTML كمرفق مع CSP sandbox؛ `no-store` و`nosniff` | مفعّل |

ينبغي ضبط `BOOK_REQUIRE_MALWARE_SCAN=true` في الإنتاج فقط بعد التأكد تشغيلياً من وجود `clamdscan` ونجاحه. في الوضع الافتراضي غير الإلزامي تسجل الملفات الجديدة الحالة `NOT_CONFIGURED` بدلاً من الادعاء بأن الملف نظيف؛ أما في الوضع الإلزامي فيفشل الرفع بإغلاق عند تعذر الاتصال بالماسح. هذا يميز بوضوح بين تكامل موجود وبين تغطية مكافحة فيروسات عاملة فعلاً.

## 5. نتائج التحقق

تمت إعادة بناء المشروع وتشغيل اختبارات المراحل المتأثرة. كما جرى فحص الحزمة الناتجة لمصارف HTML الديناميكية الشائعة وأنماط مفاتيح حساسة، وفحص اعتماديات وقت التشغيل. لا توجد نتائج Critical أو High في تدقيق الاعتماديات وقت التحقق.

| الفحص | النتيجة |
|---|---|
| `npm run lint` | ناجح — TypeScript بلا أخطاء |
| `npm run build` | ناجح — Vite + server bundle |
| `npm run test:p9` | ناجح — الرفع، MIME، البصمات، EPUB، HTML، الماسح، CORS، CSRF، SSRF، الرؤوس، grant، limits |
| `npm run test:p4` و`npm run test:p4:files` | ناجح |
| `npm run test:p6:security` و`npm run test:p6:downloads` | ناجح |
| `npm run test:p7` | ناجح |
| `npm run test:p8` | ناجح — يشمل اختبار IDOR السابق |
| بقية P0–P5 | ناجحة في تشغيل الانحدار الكامل |
| `npm audit --omit=dev` | 0 Critical، 0 High، 0 Moderate، 0 Low |
| SAST موجه | لا `dangerouslySetInnerHTML` أو `innerHTML=` أو `document.write` أو `eval` أو `new Function` في `src` و`server` |
| فحص أسرار bundle | لا أنماط `service_role` أو AWS secret key أو private key في `dist` |

## 6. مخاطر متبقية وتوصيات تشغيلية

لا توجد نتيجة High أو Critical معروفة ضمن المسارات الأساسية المراجعة. وتبقى عناصر تشغيلية لا يمكن الجزم بها من شفرة المصدر وحدها؛ أهمها تكوين reverse proxy وTLS، سياسات IAM الخاصة بمستودع S3، تشغيل ClamAV وتحديث تعريفاته، وتوزيع rate limit بين مثيلات متعددة. إن كان النشر متعدد النسخ، فيجب نقل العدادات من الذاكرة المحلية إلى Redis أو بوابة API مشتركة؛ فالحد الحالي صحيح داخل كل عملية لكنه ليس حدّاً عالمياً عبر عدة عمليات.

| أولوية | الإجراء التشغيلي | سبب الإجراء |
|---|---|---|
| عالية | تفعيل `BOOK_MALWARE_SCANNER=clamdscan` و`BOOK_REQUIRE_MALWARE_SCAN=true`، مع مراقبة صحة الماسح وتحديث تعريفاته. | يفعّل رفضاً فعلياً للبرمجيات الخبيثة بدلاً من وضع التكامل غير الإلزامي. |
| عالية | قصر IAM على bucket ومفاتيح Nexara فقط، وتفعيل تشفير S3 ومنع public ACL. | يحافظ على عزل التخزين وسلامة checksum. |
| متوسطة | استخدام Redis أو API gateway لحدود المعدل عند النشر متعدد النسخ. | يمنع تجاوز الحد بالتنقل بين مثيلات الخادم. |
| متوسطة | تشغيل DAST مصادق عليه ضد بيئة staging ثم مراجعة سجلات WAF/التطبيق. | يضيف تغطية لسلوك البروكسي والتكوين الفعلي. |
| متوسطة | إبقاء CSP ضمن وضع report-only عند أي توسعة لمصادر الصور أو الاتصال ثم تضييقها تدريجياً. | يقلل أثر تغييرات الواجهة المستقبلية دون تعطيلها فجأة. |

## 7. قرار GATE P9

> **PASS.** التحصينات المطبقة والاختبارات المنفذة لا تكشف حالياً عن ثغرة High أو Critical معروفة في مسارات الهوية، الصلاحيات، API، الرفع، التخزين، التنزيل، والمصادر الخارجية ضمن نطاق المراجعة. يجب إكمال عناصر التشغيل المذكورة أعلاه، وخصوصاً تشغيل فحص البرمجيات الخبيثة المُلزم وتوزيع rate limit عند التوسع الأفقي، قبل اعتبار الحماية الإنتاجية مكتملة تشغيلياً.
