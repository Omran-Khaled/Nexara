# P14 — بوابة الاختبارات الرئيسية

**تاريخ التنفيذ:** 18 أغسطس 2026  
**حالة المرحلة:** **PASS**  
**قرار المرحلة:** أضيفت بوابة اختبار قابلة لإعادة التنفيذ تجمع فحص النوع، وبناء الإنتاج، واختبارات الوحدة، والتكامل، والاختبارات الطرفية المنظومية. شُغِّلت البوابة بنجاح، ثم دُمجت في مشغّل القبول الكامل الذي انتهى بنتيجة **PASS P0–P14**.[1] [2]

> **تعريف البوابة:** لا تمر P14 ما لم ينجح `tsc --noEmit`، وبناء Vite/الخادم، وجميع طبقات الاختبار الثلاث. الفشل في أي طبقة يوقف المشغّل بحالة غير صفرية ويحفظ سجل التنفيذ في artefact مستقل.

## 1. ما أُضيف إلى المستودع

| الأصل | الدور التشغيلي |
|---|---|
| `tests/p14.shared.ts` | أدوات خادم HTTP المعزول، هوية الاختبار، كتاب كامل البيانات، رفع ملف حقيقي، حساب SHA-256، ومصدر إدخال موثوق حتمي. |
| `tests/p14.unit.test.ts` | اختبارات وحدة للقواعد، والخدمات، والمستودعات، وحقوق النشر، وسياسة التنزيل، وحسابات القارئ. |
| `tests/p14.integration.test.ts` | تكامل API مع تخزين محلي حقيقي وMongoDB Replica Set مؤقتة، ومسارات المصادقة والاكتشاف والتنزيل. |
| `tests/p14.e2e.test.ts` | خمسة تدفقات طرفية منظومية كاملة عبر خادم Express المعزول وواجهاته الفعلية. |
| `scripts/run-p14-master-gate.sh` | المشغّل الرئيسي لـP14؛ ينتج `artifacts/audit/p14-master-gate.log`. |
| `scripts/run-all-acceptance-audit.sh` | حُدِّث من P0–P13 إلى P0–P14 ويستدعي بوابة P14 بعد البوابات السابقة. |
| `package.json` | أوامر `test:p14:unit` و`test:p14:integration` و`test:p14:e2e` و`test:p14`. |

## 2. مصفوفة التغطية

| طبقة الاختبار | التغطية المنفذة | دليل النجاح |
|---|---|---|
| **Unit** | `validateBookWrite` و`validateBookPatch` و`validateProgress` و`validateRights`؛ حسابات نسبة تقدم القارئ ودمج التقدم الرتيب والحفظ المحلي؛ `BookService` و`ReadingService` و`RightsService`؛ مستودع التقدم داخل الذاكرة؛ سياسة `allowsFullDownload`. | اجتازت جميع التأكيدات، بما يشمل الرفض البنيوي للمدخلات غير الصالحة وحفظ أحدث تسلسل للتقدم.[3] |
| **Integration** | MongoDB حقيقية مؤقتة مع ترحيلات؛ مسارات الصحة والكتب والتقدم؛ مصادقة وهوية server-side؛ provider للاكتشاف عبر API؛ رفع ملف PDF، تفويضه، تسليمه، ومطابقة SHA-256. | اجتازت واجهات API وMongoDB والتنزيل والاكتشاف والمصادقة، مع حفظ تقدم رتيب في MongoDB.[3] |
| **System E2E** | تدفقات المكتبة والقارئ، تنزيل ملف فعلي، استعادة الجلسة والتقدم، إدخال/نشر إداري محروس، ورفض مورد محمي. | اجتازت التدفقات الخمسة، بما في ذلك حظر القارئ عن سجل التدقيق بـ`403`.[3] |
| **Build gate** | `tsc --noEmit` و`vite build` وتجميع خادم الإنتاج. | نجحت عملية البناء؛ بقي تحذير Vite غير الحاجب بشأن chunk أولي أكبر من 500 KB، وهو نفس حد المتابعة المعروف من P13.[3] [4] |

## 3. تدفقات E2E المطلوبة

الاختبارات الطرفية هنا **منظومية عبر HTTP**: تشغّل `createApp` بكل وسائط Express، وطبقات المصادقة والتفويض والخدمات والمستودعات والتخزين الفعلي داخل بيئة اختبار معزولة. وهي لا تدعي أنها اختبار Chromium لواجهة منشورة أو اختبار Supabase حي؛ فذلك يبقى خارج موارد هذه الجلسة كما أوضح تدقيق P0–P13.[4]

| التدفق | الخطوات المثبتة | النتيجة المتحققة |
|---|---|---|
| **1. Library → Reader** | liveness، قائمة مكتبة منشورة، تفاصيل كتاب كامل، فتح جلسة قراءة، الفصل الأول، تغيير إلى الفصل الثاني، حفظ التقدم، ثم قراءة تاريخ الجلسة. | ظهرت أحداث `OPENED` و`PROGRESS_SAVED`، وحُفظ موضع الفصل الثاني. |
| **2. Download → checksum** | رفع PDF حقيقي بصفته مديراً، إصدار رابط تنزيل للقارئ، تنزيل البايتات، ثم حساب SHA-256. | تطابقت بصمة الملف المسلم تماماً مع بصمة الملف الأصلي. |
| **3. Login → save → restore** | حلّ هوية قارئ، إنشاء bookmark، حفظ تقدم أحدث، طلب بلا هوية لتقليد logout، ثم إعادة حل الهوية وجلب الرف والتقدم. | رُفضت الجلسة الفارغة بـ`401`، وعادت العلامة ونسبة التقدم `82%` بعد إعادة الدخول. |
| **4. Admin → validate → upload → publish** | بدء إدخال Gutenberg من مصدر حتمي، التحقق من مرحلتي الحقوق والملف، فحص سجل الحقوق، رفع ملف إداري، نشر Job، ثم فحص قائمة القارئ وفصل الكتاب المنشور. | بقي النشر محروساً داخل ingestion؛ ظهر الكتاب المنشور للقارئ وأصبح فصله قابلاً للقراءة. |
| **5. Protected resource denied** | قارئ يطلب `/api/audit-logs`. | استجاب النظام بـ`403`، مؤكداً عدم تسرب بيانات التدقيق لمستخدم غير مخوّل. |


## 5. دليل إعادة التنفيذ

بدأ تنفيذ بوابة P14 المسجل في الأثر النهائي عند `2026-08-18T16:01:28Z` وانتهى عند `2026-08-18T16:01:43Z` بنتيجة **PASS**؛ تضمن فحص النوع والبناء وجميع الطبقات الجديدة.[3] بعد ذلك نُفّذ مشغّل القبول الموحد، وانتهى صراحة بـ`Summary: PASS P0-P14`.[2]

## 6. حدود الدليل التي تظل قائمة

نجاح P14 يعني أن الشفرة اختبرت بقوة داخل بيئة معزولة: MongoDB مؤقتة، تخزين محلي مؤقت، مزوّد اكتشاف حتمي، وهويات اختبار server-side. ولا يعني ذلك تحققاً من MongoDB أو S3/R2 أو Supabase أو ClamAV أو DNS/TLS أو CI سحابي أو حسابات مستخدمين حقيقية. وتبقى متطلبات إغلاق البيئة الحية الموضحة في تدقيق P0–P13 قائمة قبل إعلان نشر إنتاجي مكتمل بلا فجوات.[4]

## 7. الخلاصة

> **قرار P14: PASS.** أصبحت للمشروع بوابة رئيسية عملية قابلة لإعادة التنفيذ، وتغطي فئات الاختبار المطلوبة دون ادعاء اختبار موارد حية غير متاحة. كما أصبح القبول الموحد يضم P14 رسمياً وينتهي بنتيجة **PASS P0–P14**.
