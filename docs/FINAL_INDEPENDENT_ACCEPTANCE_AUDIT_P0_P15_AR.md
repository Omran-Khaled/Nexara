# التدقيق المستقل الصارم — Nexara P0–P15

**تاريخ التدقيق:** 18 أغسطس 2026  
**النطاق:** الشفرة الحالية، التثبيت المقفل، مشغلات القبول، الاختبارات، بيئة MongoDB المؤقتة، التخزين المحلي المعزول، والمصادر العامة التي يستدعيها اختبار P15 الحي.  
**خارج النطاق لغياب مورد قابل للاستخدام:** MongoDB وS3/S3-compatible وSupabase وClamAV ودومين/Proxy/CI حقيقية تابعة للمستخدم.

> **الحكم الصريح:** تقبل الشفرة والمستودع عبر **P0–P15 قبولاً مشروطاً (CONDITIONAL PASS)**. أعيد تثبيت الاعتماديات من القفل، وأعيد تشغيل القبول الكامل فنجحت **31/31 بوابة P0–P10** ثم P11–P15، وانتهى السجل بـ`PASS P0-P15`.[1] لا توجد حالياً فجوة برمجية مؤكدة أو بوابة قبول فاشلة داخل البيئة المعزولة. لكن لا يمكن مهنياً وصف المشروع بأنه «مكتمل بلا أي فجوة إنتاجية» لأن تكاملات المستخدم الحية المذكورة أعلاه غير متاحة، ولذلك لا يرقى الحكم إلى **PASS إنتاجي مطلق**.

## 3. تدقيق متطلبات P14

تثبت P14 بشكل صريح طبقة الوحدة للـvalidators والخدمات والمستودعات والحقوق وقواعد التنزيل وحسابات القارئ. كما تثبت طبقة التكامل MongoDB المؤقتة ومسارات API والمصادقة التجريبية والاكتشاف، وترفع بايتات ملف ثم تعيد تنزيله وتطابق SHA-256 من الطرف إلى الطرف.[4]

التدفقات الخمسة المنفذة هي: فتح المكتبة والقارئ وتغيير فصل وحفظ التقدم؛ تنزيل ملف فعلي والتحقق من البصمة؛ تسجيل جلسة تجريبية وحفظ كتاب واستعادة التقدم؛ إدخال إداري والتحقق من الحقوق والملف والنشر ثم ظهوره للقارئ؛ ومنع قارئ عادي من audit logs.[4]

> **حد مهم:** وصف «E2E» في P14 دقيق فقط بمعنى **اختبار نظام HTTP**. الاختبار يستخدم `allowTestIdentity` ومستودعات in-memory لبعض التدفقات، ولا يفتح Chromium ولا يسجل دخول مستخدم Supabase حقيقي. هذا ليس عيباً في الشفرة، لكنه يمنع اعتباره دليلاً كاملاً على تجربة المتصفح أو هوية الإنتاج.

## 4. تدقيق متطلبات P15

أعاد الاختبار الحي استدعاء `catalog:ingest` نفسه ضد Standard Ebooks في MongoDB وتخزين محليين مؤقتين، وأثبت نشر **3 كتب** مع **3 EPUBs موثقة** و**3 سجلات حقوق** و**115 فصلاً مقروءاً** و**3 أغلفة**.[1] يستبعد أمر الإنتاج التخزين المحلي عندما تكون `NODE_ENV=production` ويطلب MongoDB وS3-compatible storage.[6]

وجد هذا التدقيق أن اختبار P15 الدائم كان يثبت سابقاً حالتي الحقوق الناقصة وEPUB الفاسد فقط. عولجت فجوة التغطية فوراً بإضافة حالات رفض دائمة لـmetadata الناقصة، المصدر غير الموثوق، الملف المفقود، والفصول غير القابلة للقراءة. اجتاز الاختبار الموسع ثم اجتاز القبول الكامل من جديد.[5] وبذلك أصبحت كل قواعد الرفض الواردة في طلب P15 قابلة لإعادة التنفيذ داخل البوابة.

## 6. الحدود والفجوات التي لا يمكن ادعاء إغلاقها

| بند غير متحقق | لماذا لا يعد PASS | ما يلزم للإغلاق |
|---|---|---|
| MongoDB الحقيقية | لا URI أو صلاحيات cluster في الجلسة. | staging/prod URI محدود الصلاحية، migration وsmoke حقيقي. |
| S3/R2/MinIO الحقيقي | لا bucket أو credentials، فلا HeadBucket أو signed URL حقيقية. | bucket اختبار وبيانات اعتماد محدودة الصلاحية، upload/download/delete. |
| Supabase الحقيقي | لا publishable key أو حسابات اختبار للمشروع. | مستخدم reader وadmin اختباريان، session/OAuth وتفويض role assignment حقيقي. |
| ClamAV الحقيقي | `clamdscan` غير مثبت. | تشغيل الماسح مع `BOOK_REQUIRE_MALWARE_SCAN=true` ثم readiness ورفع ملف آمن/خبيث تجريبي. |
| GitHub Actions الخارجي | workflow عُدّل وفُحص محلياً فقط. | push وتشغيل workflow ناجح على repository المستخدم. |
| DNS/TLS/Proxy/CDN | لا دومين منشور. | فحص HTTPS/HSTS/CORS والرؤوس خلف proxy حقيقي. |
| Browser E2E مستخدم حقيقي | P14 HTTP system test وليس متصفحاً أو Supabase. | Playwright/Chromium على staging مع حسابات اختبار صريحة. |
| RUM/load test | P13 محلي. | telemetry وقياس أداء/ضغط ببيانات وحركة مماثلة للإنتاج. |

## 7. القرار النهائي

> **قرار قبول المستودع والشفرة P0–P15: CONDITIONAL PASS.** لا توجد بوابة قبول فاشلة بعد إعادة التثبيت النظيف وإعادة تنفيذ المسار الكامل، وأُغلقت فجوتا أثر CI وتغطية جودة P15 اللتان كشفهما التدقيق.
>
> **قرار الجاهزية للإنتاج الحي: غير مكتمل الإثبات.** لا يصح وصف المشروع بأنه متكامل إنتاجياً «بلا أي فجوات أو أخطاء» قبل تنفيذ بنود القسم 6 في بيئة staging/production مصرح بها. هذه حدود دليل، لا ادعاءات بفشل لا يمكن إثباته.

## 8. ملحق تدقيق الواجهة الأمامية التفاعلي

بعد التدقيق الأصلي، نُفّذ تدقيق Chromium تفاعلي مستقل على بيئة المعاينة المتكاملة ذات الكتالوج الحقيقي. غطى التدقيق الشريط العلوي، القوائم المتحركة، المسارات العميقة للكتب والمؤلفين، الغابة، التجوال، المزاج، المسارات، الخريطة، البحث الحي، طقس القراءة، استوديو الاقتباسات، المكتبة الشخصية، المجتمع، ولوحة الإدارة. كما فُحصت ثماني واجهات على محاكاة هاتف 390×844 من دون تجاوز عرض أفقي.[8]

أسفر التدقيق عن إصلاحات واجهة مؤكدة: معالجة الروابط العميقة للكتاب والمؤلف، حقول سيرة/لغة المؤلف، تناوب التجوال، مطابقة بوابات المزاج بالكتالوج الحقيقي، التاريخ غير المتاح في نتائج البحث الحي، حالة المسارات الفارغة، وصلاحيات لوحة الإدارة المرئية للضيف، بالإضافة إلى حمايات الصور البديلة. أعيد تنفيذ `npm run lint` و`npm run test:ui` وبناء الإنتاج ثم `scripts/run-all-acceptance-audit.sh`؛ وانتهت بوابة القبول في 18 أغسطس 2026 عند 17:59:42Z بـ`Summary: PASS P0-P15`.[8]

> **تعديل حد الدليل:** أصبح لدى المشروع دليل تفاعل Chromium للضيف ولقطات هاتف محلية، لكنه لا يزال لا يملك Browser E2E مع حساب Supabase حقيقي أو صلاحيات محرر إنتاجية. لذلك يبقى حكم **CONDITIONAL PASS** سليماً، مع تقوية الدليل الخاص بالواجهة المحلية.
