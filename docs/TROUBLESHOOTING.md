# استكشاف أعطال Nexara

## قواعد التشخيص

ابدأ دائماً من نسخة البيئة والمسار المتأثر ووقت حدوث المشكلة، ثم افحص `/api/health/ready`. لا تنسخ مفاتيح البيئة أو access tokens أو روابط التنزيل الموقعة إلى تذكرة دعم أو سجل عام.

| العرض | ما يجب فحصه | الإجراء الآمن |
|---|---|---|
| الخادم لا يبدأ | سجل البدء و`NODE_ENV` و`MONGODB_URI` وتهيئة S3. | أصلح المتغير الناقص؛ لا تشغل إنتاجاً بتخزين محلي. |
| readiness يعيد 503 | عنصر التبعية الفاشل في التقرير. | أزل النسخة من التوزيع، ثم أصلح MongoDB أو S3 أو Supabase أو ClamAV. |
| liveness ناجح وreadiness فاشل | هذا متوقع عند فقد تبعية خارجية. | لا تفسر liveness كصحة إنتاجية؛ اعتمد readiness. |
| تسجيل الدخول لا يعمل | `SUPABASE_URL` والمفتاح publishable وحالة `/api/supabase/status` وCORS. | أصلح مشروع/مفتاح البيئة، ثم اختبر حساباً حقيقياً. |
| المستخدم يحصل على 403 | bearer token والدور الخادمي وملكية المورد. | لا تضف bypass أو رأس اختبار؛ راجع إسناد الدور في الخادم. |
| رفض CORS | origin الحقيقي وقائمة `NEXARA_CORS_ORIGINS`. | استخدم origin HTTPS كاملاً بلا مسار، ثم أعد النشر. |
| فشل رفع ملف | MIME والامتداد والتوقيع والحجم وصحة EPUB/HTML وClamAV. | استبدل الملف من مصدر موثوق؛ لا تعطّل الفحص. |
| فشل تنزيل | حقوق النسخة والملف المنشور وصلاحية الرابط الموقّع. | اطلب رابطاً جديداً من التطبيق؛ لا تعيد استعمال رابط منتهٍ. |
| لا يظهر كتاب للمستخدم | حالة وظيفة الإدخال والحقوق والفصول والملف وحالة النشر. | لا تنشر يدوياً قبل اجتياز المراحل؛ راجع المرشح. |

## فشل MongoDB

تحقق من DNS والشبكة وallowlist وحساب التطبيق وصلاحياته واسم قاعدة البيانات. لا يملك التطبيق بديلاً دائماً آمناً عندما تكون MongoDB غير متاحة، لذلك يجب أن يعيد readiness حالة غير جاهزة. إذا كانت المشكلة واسعة، نفذ خطة التعافي من [دليل النسخ والاستعادة](BACKUP_AND_RECOVERY.md) بعد إيقاف الكتابات وتحديد نقطة الاستعادة المقبولة.

## فشل التخزين المتوافق مع S3

تحقق من bucket وendpoint والمنطقة ومفاتيح IAM ومنع الوصول العام. شغّل `npm run production:preflight` من نفس شبكة عملية Nexara؛ يختبر صحة bucket من دون طباعة أسرار. لا توجه التنزيلات إلى ملفات محلية ولا تستخدم بيانات placeholder عند الفشل.

## فشل Supabase Auth

اختبر `/api/supabase/status` ثم اختبر تسجيل دخول بحساب حقيقي. تأكد من تطابق عنوان Supabase في متغيرات الخادم و`VITE_` ومن أن origin الموقع مسموح في إعدادات Supabase. إذا كانت الجلسة صحيحة لكن API ترفضها، راجع تعيين الدور في MongoDB بدلاً من تغيير واجهة المتصفح.

## فشل ClamAV

تأكد من وجود `clamdscan` في بيئة عملية Nexara ومن وصوله إلى daemon. عندما يكون `BOOK_REQUIRE_MALWARE_SCAN=true`، يجب أن يبقى readiness غير جاهز إذا تعذر الفحص. لا تحول المتغير إلى `false` كحل حادث؛ أصلح الخدمة ثم أعد preflight.

## فشل بعد نشر إصدار

نفذ `NEXARA_DEPLOY_URL=https://<domain> npm run production:smoke`. إذا فشل health أو readiness أو Supabase أو الكتالوج، أخرج الإصدار الجديد من موازن الحمل ونفذ rollback للإصدار السابق المتوافق. لا تستعد قاعدة البيانات قبل مراجعة migration وخطة الاستعادة، ولا تخفف CORS أو التفويض لتمرير اختبار.
