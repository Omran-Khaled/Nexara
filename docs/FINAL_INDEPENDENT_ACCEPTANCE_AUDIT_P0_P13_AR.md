# التدقيق المستقل الشامل — Nexara P0–P13

**تاريخ التدقيق:** 18 أغسطس 2026  
**نطاق التدقيق:** الأرشيف الحالي للمشروع وبيئة اختبار معزولة؛ لا يشمل حسابات المستخدم أو موارده السحابية الحية أو نشره الفعلي.  
**المنهج:** تثبيت نظيف من `package-lock.json`، إعادة تنفيذ بوابات P0–P13، بناء إنتاج، تدقيق اعتماديات، فحص تشغيل مع MongoDB مؤقتة، تدقيق ثابت، قياس إنتاج محلي عبر Chromium، واختبار مشغل القبول الموحد.

> **القرار الصريح:** الشفرة ضمن نطاق المراحل **P0–P13 تمر بنجاح**؛ لا توجد بوابة قبول فاشلة أو عيب برمجي حرج/عالٍ مؤكد في الأدلة التي أعيد تنفيذها. لكن لا يمكن مهنياً إعلان أن الخدمة الحية للمستخدم «متحقق منها بالكامل بلا فجوات» لأن MongoDB وS3 وSupabase وClamAV الحقيقية، الدومين/proxy، وتنفيذ CI الخارجي لم تكن متاحة لهذه الجلسة. لذلك قرار النشر الحي هو **CONDITIONAL**، لا **PASS مطلق**.

## 1. دليل إعادة التنفيذ

أعيد إنشاء `node_modules` عبر `npm ci --ignore-scripts` بنجاح، ثم نفذ المشغل الأساسي P0–P10 **31 بوابة** بنتيجة `pass=31, fail=0`. بعد ذلك نفذت بوابات P11 وP12 وP13 وفحص تشغيل الخادم الفعلي مع MongoDB مؤقتة بنجاح. وأضيف مشغل موحد `scripts/run-all-acceptance-audit.sh` وملف CI في GitHub Actions، ثم شُغّل المشغل محلياً بنجاح عبر P0–P13.

| المجال | الدليل الذي أعيد تنفيذه | النتيجة |
|---|---|---:|
| تثبيت الاعتماديات | `npm ci --ignore-scripts` | **PASS**؛ 318 حزمة مدققة، ولا ثغرات أبلغ عنها npm في تلك العملية. |

## 3. إصلاحات موثقة أثناء التدقيق

كشف التدقيق أن الأرشيف لا يحوي مشغلاً موحداً لكل المراحل أو workflow للتكامل المستمر، رغم وجود مشغل P0–P10. هذه فجوة **قابلية إعادة التحقق داخل المستودع** وليست عيباً في منطق التطبيق. عولجت بإضافة:

| البند | الإجراء | إثبات الأثر |
|---|---|---|
| قبول P0–P13 الموحد | `scripts/run-all-acceptance-audit.sh` | شغّل محلياً بنجاح وكتب سجل `artifacts/audit/p0-p13-execution.log`. |
| CI المصدرية | `.github/workflows/acceptance.yml` | يثبت نسخة Node 22.13.0، تثبيتاً مقفلاً، ومشغل القبول، ويرفع artefacts التدقيق. |

لم يضف التدقيق تحسينات وظيفية غير مبررة أو ادعاء اختبار لم ينفذ. ولا تزال أي فجوة خاصة بموارد المستخدم الحية مصنفة بوضوح أدناه.

## 4. ما ثبت تقنياً

يبدأ الخادم مع MongoDB مؤقتة، يطبق الترحيلات، ويفصل liveness عن readiness. عند تعطل تبعية مطلوبة، يعيد readiness حالة `503` بدلاً من نجاح Express سطحي. كما أن سجل الطلب المنظم يحمل request ID والمسار والحالة والكمون، ويضيف المستخدم عند توفر principal، وتغطي البوابة أخطاء قاعدة البيانات والمصادقة والتنزيلات.[1]

تثبت P11 أن مكتبة المستخدم والمجتمع لا يعرضان رصيداً شخصياً ثابتاً: الفحص يختبر تاريخ القراءة، عضوية الرف، مراجعة دائمة، إعجاب، نقاش، ومنع المراجعة المكررة. وتثبت P13 أن التحميل الكسول خفض مدخل JavaScript الأولي من 898,348 بايت إلى 662,503 بايت خاماً، ومن 251,164 إلى 193,682 بايت gzip؛ لذلك يبقى التحسين المطبق مدعوماً بقياس لا بادعاء أفضل ممارسة.[2] [3]

## 5. الفجوات التي لا يجوز إخفاؤها

هذه ليست بوابات برمجية فاشلة، لكنها تمنع إصدار حكم «إنتاج حي كامل بلا فجوات» في جلسة لا تملك موارد المستخدم أو صلاحيتها.

| الفجوة | الحالة | الأثر | ما يلزم للإغلاق |
|---|---|---|---|
| MongoDB الحقيقية | غير متحققة | لم يثبت الاتصال أو صلاحيات cluster أو النسخ الاحتياطي الفعلي. | URI staging/production، migration، وsmoke عبر الدومين الفعلي. |
| S3/R2/MinIO الحقيقي | غير متحقق | لا يمكن إثبات `HeadBucket` أو upload/download أو روابط موقعة حقيقية. | بيانات اعتماد محدودة الصلاحية وbucket اختبار. |
| Supabase الحقيقي | غير متحقق | لم يثبت OAuth/session/roles لمستخدم فعلي. | حسابات اختبار، أدوار Mongo، واختبار E2E عبر المجال. |
| ClamAV الحقيقي | غير متحقق | `clamdscan` غير موجود في بيئة التدقيق؛ لا يمكن اعتماد رفع يتطلبه في الإنتاج. | تثبيت/تشغيل ClamAV و`BOOK_REQUIRE_MALWARE_SCAN=true` ثم readiness/رفع آمن. |
| GitHub Actions الخارجي | غير متحقق | workflow موجود ومدقق محلياً فقط؛ لم ينفذ على repository المستخدم. | رفع المستودع وتشغيل workflow في GitHub. |
| نشر/DNS/proxy/CDN | غير متحقق | لا دليل على HTTPS/HSTS أو حفظ رؤوس الأمان أو CORS خلف proxy. | نشر staging، فحص رؤوس خارجي، وتأكيد DNS/TLS. |
| أداء مستخدمين حقيقيين | غير متحقق | P13 محلي ومنضبط، وليس RUM أو حمل WAN. | telemetry/RUM وload test وفق حجم الكتالوج وحركة الإنتاج. |

يوجد أيضاً تحذير بناء غير حاجب: مدخل JavaScript الأولي أصبح `662.5 KB` خاماً، وهو أفضل بنسبة 26.25% من خط الأساس لكنه ما زال فوق تحذير Vite البالغ 500 KB. P13 لم تضف splitting إضافياً بلا دليل استخدام؛ القرار الصحيح هو قياس RUM قبل أي تقسيم آخر.[3]

## 6. القرار النهائي

> **قرار قبول الشفرة والمراحل P0–P13: PASS.** أعيدت بوابات القبول من تثبيت نظيف، ونجحت 31/31 بوابة P0–P10، وبوابات P11–P13، والبناء، والتدقيق الاعتمادي، وفحص تشغيل الخادم مع MongoDB مؤقتة. لا توجد فجوة برمجية مؤكدة أو خطأ اختبار ظاهر في الأدلة الحالية.
>
> **قرار التكامل المستودعي: PASS مع إغلاق فجوة CI.** أصبح هناك مشغل موحد P0–P13 وworkflow CI قابل للتنفيذ عند رفعه إلى GitHub.
>
> **قرار الجاهزية للإنتاج الحي: CONDITIONAL.** لا أستطيع، ولا ينبغي لأي تدقيق أمين، إعلان موارد غير متاحة أو حسابات أو proxy أو ClamAV أو GitHub Actions منفذة فعلاً. لا يوجد دليل يثبتها في هذه الجلسة، ولذلك تبقى قائمة الإغلاق في القسم 5 إلزامية قبل وصف الخدمة المنشورة بأنها مكتملة بلا فجوات.
