# حالة أساس Nexara قبل النشر

**تاريخ التحديث:** 19 أغسطس 2026  
**الحكم الحالي:** **الأساس التقني جاهز للنشر لاحقاً، لكنه ليس إصدار إنتاج منشوراً بعد.**

تم تجهيز Nexara ليعمل كتطبيق Express قابل للاستدعاء من وظيفة Vercel مع إبقاء خادم التطوير المحلي مستقلاً. كما أضيفت نقطة API في `api/index.ts` وملف `vercel.json` وبناء واجهة مستقل عبر `npm run build:client`. يعالج هذا الفصل اختلاف طريقة الاستضافة، إذ يتحول تطبيق Express على Vercel إلى وظيفة واحدة وتُقدم الواجهة من ناتج البناء بدلاً من `express.static()` داخل الوظيفة [1].

| المجال | ما تم تنفيذه وإثباته | الحالة |
|---|---|---|
| البيانات | تم ربط MongoDB Atlas، وتشغيل migration `p15-real-initial-catalog-v1`، وتثبيت أدوار المستخدمين في `role_assignments`. | مثبت حيّاً |
| المصادقة | تم التحقق من Supabase Auth، وإنشاء حساب القارئ `reader1@nxara.com` بالتأكيد التلقائي، وإسناد دور `READER`. كما أُسند دور `ADMIN` للحساب الإداري القائم. | مثبت حيّاً |
| التخزين | تم استخدام bucket خاص `nexara-books` عبر endpoint S3 المتوافق، ونجحت عمليات HeadBucket والرفع والقراءة والروابط الموقعة للقراءة والكتابة والحذف. | مثبت حيّاً |
| رفع الكتب الكبيرة | أضيف مسارا `direct-upload` و`complete-direct-upload` لإرسال الملف من المتصفح مباشرة إلى S3 برابط قصير العمر ثم استرجاعه وفحصه خادمياً قبل النشر. | جاهز برمجياً |
| الفحص الأمني | أضيف محول `remote-http` لخدمة فحص خارجية، مع خدمة مرجعية مستقلة في `services/clamav-scanner/` وحاوية تشغيل. | جاهز برمجياً، غير منشور |
| بنية Vercel | أضيف إعداد Vercel ومدخل API وبناء عميل منفصل. | جاهز للنشر، غير منشور |
| التحقق المحلي | نجح فحص الأنواع والبناء، واختبارات P4 للملفات وP9 للتقوية الأمنية، وبوابة القبول P0–P15 كاملة. | مثبت |
| التحقق الحي | نجح اختبار runtime مع MongoDB وSupabase وS3، ونجح دخول القارئ الحي مع ظهور دور `READER` ورفض محاولة رفع إداري بـ`403`. | مثبت حيّاً |

> لا تمرر الكتب الكبيرة عبر وظيفة Vercel نفسها. تضع Vercel حداً لحجم جسم طلب/استجابة الوظيفة قدره 4.5MB، لذلك اعتمد Nexara الرابط الموقّع المباشر إلى التخزين الخاص للرفع [2].

## عناصر مؤجلة عمداً حتى مرحلة النشر

| الشرط المتبقي | سبب عدم تنفيذه الآن | الإجراء المطلوب قبل الإطلاق |
|---|---|---|
| مشروع Vercel فعلي | طُلب عدم النشر الآن. | إنشاء/ربط مشروع Vercel، إدخال متغيرات البيئة السرية، ونشر Preview أولاً. |
| خدمة ClamAV حية | تحتاج بيئة حاويات مستقلة ورابط HTTPS ورمز خادمي. | نشر `services/clamav-scanner/`، ثم ضبط `BOOK_MALWARE_SCANNER=remote-http` وURL وtoken، وتفعيل `BOOK_REQUIRE_MALWARE_SCAN=true`. |
| اختبار رفع وفحص كامل | يتطلب خدمة الفحص الحية. | رفع ملف اختبار عبر الرابط المباشر، إكمال الفحص، والتحقق من رفض ملف مُصاب. |
| اختبار مدير حي | لا توجد كلمة مرور اختبار خاضعة لإدارة Nexara للحساب الإداري القائم. | إنشاء حساب مدير اختبار مستقل أو اعتماد اختبار دخول المدير من المالك، ثم إثبات إدارة المحتوى والأدوار. |
| نسخ واستعادة حيّان | لا يجب تنفيذ استعادة مدمرة على بيانات حية بلا نافذة صيانة. | إجراء نسخة MongoDB ونسخة كائنات، ثم استعادة في بيئة معزولة وتوثيق زمن الاستعادة. |
| تقييد Atlas | فُتح `0.0.0.0/0` مؤقتاً لتجاوز عنوان خروج اختبار متغير. | إزالة القاعدة المفتوحة قبل الإنتاج ووضع سياسة وصول مقيدة مناسبة لبيئة الاستضافة. |

## تسلسل النشر لاحقاً

ابدأ بإغلاق الوصول المفتوح في Atlas واستبداله بوصول مقيد لبيئة الاستضافة. بعد ذلك انشر خدمة الفحص المستقلة واختبر `/health` منها، ثم عيّن متغيرات Vercel الخادمية فقط. شغّل `npm run db:migrate` كعملية نشر مضبوطة، وليس في مسار cold start، ثم انشر Preview. بعد نجاح `production:preflight` و`production:smoke` واختبار رفع وفحص وقراءة وتنزيل بحسابي القارئ والمدير، يمكن ترقية Preview إلى الإنتاج.
