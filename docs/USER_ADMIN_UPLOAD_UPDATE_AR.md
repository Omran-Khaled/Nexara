# تحديث إعدادات المستخدمين ولوحة المدير ورفع الكتب

**التاريخ:** 19 أغسطس 2026  
**النطاق:** تحسين تجربة الحساب، إدارة الأدوار، ورفع ملفات الكتب من داخل Nexara دون الحاجة إلى لوحة S3.

## ما تم تنفيذه

| المجال | الوظيفة المنفذة | الضابط الأمني |
|---|---|---|
| إعدادات المستخدم | تعديل الاسم المعروض والاسم العربي من نافذة الحساب. | التحديث يتم عبر جلسة Supabase الحالية فقط. |
| كلمة المرور | نموذج مستقل لتحديث كلمة المرور مع حد أدنى 10 أحرف. | لا تمر كلمة المرور عبر API Nexara؛ تعالجها Supabase Auth. |
| الدور الفعلي | بعد تسجيل الدخول تستدعي الواجهة `/api/auth/me` وتعرض الدور الذي أعاده الخادم. | لا تقبل الواجهة دوراً مخزناً محلياً كصلاحية. |
| إدارة الأدوار | تبويب **المستخدمون والأدوار** في لوحة الإدارة لإسناد/إزالة أدوار المستخدمين المعروفين بمعرف UUID. | API خادمي وصلاحية `ROLE_MANAGE` وحماية من التصعيد الذاتي. |
| إنشاء السجل | نموذج إنشاء كتاب يدعم اختيار مؤلف موجود أو إدخال مؤلف جديد عند كون الفهرس فارغاً. | يبقى السجل `METADATA_ONLY` إلى أن يمر الملف والحقوق بالتحقق. |
| رفع الكتب | تبويب **رفع كتاب** يختار كتاباً وإصداراً وملفاً ثم يرفعه مباشرة برابط S3 موقع. | الرابط قصير العمر؛ يعيد الخادم قراءة الملف وفحصه والتحقق من الحقوق قبل ربطه بالإصدار. |

## مسار رفع الكتاب

يختار المدير أولاً سجل الكتاب والإصدار، ثم ملفاً بصيغة PDF أو EPUB أو TXT أو HTML، ويمكنه إدخال رابط مصدر أو رخصة وتحديد سياسات القراءة والتنزيل والوصول دون اتصال. يتحقق العميل من الحجم (50MB كحد حالي) والصيغة، ثم يطلب من Nexara رابط كتابة موقّعاً. يُرسل المتصفح الملف مباشرة إلى التخزين الخاص، ثم يستدعي Nexara خطوة إتمام الرفع.

في خطوة الإتمام، لا يثق Nexara بالملف الموجود في التخزين وحده. يسترجعه الخادم، ويطبق فحص النوع والحجم والسلامة والمحتوى وفحص البرمجيات الضارة عند تفعيله، ثم ينشئ سجل الملف ويربطه بالإصدار أو يحذف الملف المرحلي عند الفشل. لذلك لا يحتاج المدير إلى دخول S3 ولا يحصل المتصفح على مفتاح S3 دائم.

> لا تصبح هذه العملية دليلاً على صحة حقوق النشر تلقائياً. يجب على المدير توفير المصدر/الرخصة وإجراء المراجعة التحريرية قبل إتاحة القراءة أو التنزيل.

## التحقق المنفذ

| التحقق | النتيجة |
|---|---|
| `npm run lint` | نجح. |
| `npm run build` | نجح. |
| `npm run test:p8` | نجح: المصادقة والأدوار ومنع تعديل الموارد والصلاحيات غير المسموحة. |
| `npm run test:p4:files` | نجح: طبقة ملفات الكتب. |
| `npm run test:p10` | نجح: بنية الواجهة والتنقل وإتاحة الحوارات. |
| فحص واجهة القارئ الحي | نجح: ظهر دور `READER` من الخادم، وظهرت إعدادات الحساب، وبقيت إدارة المحتوى مقيدة. |

## متطلب قبل الإنتاج

ينبغي تشغيل خدمة الفحص الخارجية وضبط `BOOK_REQUIRE_MALWARE_SCAN=true` قبل إطلاق الإنتاج. في بيئة التطوير الحالية يمكن اختبار الربط والتخزين، لكن لا يجب استخدام إعداد يتجاوز فحص البرمجيات الضارة لإتاحة رفع الكتب للمستخدمين الفعليين.
