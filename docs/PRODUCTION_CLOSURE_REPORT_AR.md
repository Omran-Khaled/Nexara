## 1. ما تم التحقق منه فعلياً

| النطاق | الدليل المنفذ | النتيجة |
|---|---|---|
| تثبيت الاعتماديات | `npm ci --ignore-scripts`. | نجح؛ أضيفت 317 حزمة ولم يسجل npm ثغرات معروفة في هذه الجولة. |
| سلامة الأنواع | `npm run lint`. | نجح. |
| حزمة الإنتاج | `npm run build`. | نجح؛ بنيت الواجهة و`dist/server.cjs`. ظهر تحذير حجم bundle أكبر من 500KB، وليس فشل بناء. |
| التقوية الأمنية | `npm run test:p9`. | نجح، بما فيه CORS وCSRF ورفع الملفات وClamAV التجريبي والحدود. |
| قبول المشروع | `bash scripts/run-all-acceptance-audit.sh`. | نجح من P0 إلى P15، وانتهى بـ`Summary: PASS P0-P15` عند 20:04:32Z. |
| فشل الإعداد الآمن | `NODE_ENV=production npm run production:preflight`. | فشل كما يجب بسبب غياب مفتاح Supabase publishable في البيئة، ولم يبدأ تشغيل ناقص. |

## 2. ما الذي تم إصلاحه أو إضافته

| التغيير | الأثر |
|---|---|
| عقد إعداد إنتاج مركزي في `server/config/env.ts`. | يتحقق من نوع البيئة، URLs، origins الدقيقة، حجم الرفع، التخزين S3 ومفاتيحه، وسياسة ClamAV والوكيل العكسي. |
| ربط `server.ts` بعقد التخزين الموحد. | لا يعتمد تشغيل الخادم الحقيقي على قراءات بيئة متناثرة؛ ويبقى التخزين المحلي محظوراً في الإنتاج. |
| `NEXARA_STARTUP_READINESS_REQUIRED=true`. | يمكن للإطلاق الحقيقي أن يرفض الاستماع إذا فشلت MongoDB أو التخزين أو Supabase أو ClamAV المطلوبة. |
| `NEXARA_TRUST_PROXY_HOPS`. | يضبط ثقة Express في الوكيل العكسي بدلاً من افتراضها. |
| `scripts/production-preflight.ts`. | يثبت الاتصال الحقيقي بـMongoDB وbucket وSupabase وClamAV قبل النشر من دون طباعة أسرار. |
| `scripts/production-smoke.ts`. | يختبر HTTPS والصحة والجاهزية وSupabase والكتالوج المنشور بعد الإطلاق. |
| تأكيد حذف سجل الفهرس في لوحة الإدارة. | لا ينفذ الإجراء المدمر بضغطة واحدة؛ ويعرض تحذيراً بعدم استخدام الحذف بديلاً عن إيقاف النشر. |
| مستندات التشغيل المطلوبة. | أضيفت أو استبدلت الأدلة المطلوبة، وتفرق بين الوظائف الفعلية والفجوات. |

## 3. الخدمات الحقيقية التي اختبرت

لم يختبر أي اتصال بخدمة إنتاج حقيقية، لأن متغيرات MongoDB وS3 ومفتاح Supabase publishable وأصل CORS وClamAV لم تكن متاحة. المتغير `SUPABASE_URL` العام المتاح في البيئة لا يكفي لعقد Nexara ولا يتضمن المفتاح publishable الخاص بالمشروع؛ لم يستخدم كبديل.

## 4. الاختبارات المنفذة ونتائجها

المذكور في قسم التحقق هو النطاق المنفذ فعلاً. تغطي بوابة P0–P15 بيانات اختبار وMongoDB مؤقتة ومحاكيات حيث يحددها المشروع، ولا تثبت حسابات Supabase حية أو bucket S3 أو DNS/TLS أو ClamAV حقيقياً. الاختبارات الحية الإلزامية المتبقية موضحة في دليل النشر.

## 5. ما بقي غير قابل للتحقق

| البند | سبب عدم التحقق | شرط الإغلاق |
|---|---|---|
| MongoDB حقيقية | لا يوجد URI أو حساب staging. | preflight، migration، استعلامات، وتمرین استعادة. |
| Supabase Auth حقيقية | لا يوجد مفتاح publishable ولا حسابات اختبار. | signup/login/logout/session/role بحساب قارئ ومدير. |
| S3/R2/MinIO حقيقي | لا يوجد bucket أو IAM أو endpoint. | HeadBucket ورفع وchecksum وتنزيل وحذف محكوم. |
| ClamAV حقيقي | `clamdscan` غير متاح في البيئة. | readiness وفحص نظيف ورفض عينة اختبار آمنة. |
| HTTPS/DNS/CI/CD | لا يوجد نطاق أو pipeline أو repository متصل. | فحص TLS وCORS وheaders وإطلاق مكرر. |
| مستخدم ومدير حقيقيان | لا يوجد حسابان مصرحان أو بيئة منشورة. | تنفيذ تدفقات user/admin بالكامل وحفظ أدلتها. |
| النسخ والاستعادة | لا توجد موارد إنتاج للنسخ. | تمرين استعادة معزول موثق. |
| إدارة المؤلفين/المستخدمين وتقارير التنزيلات من الواجهة | لا توجد شاشة مدعومة لها في النسخة الحالية. | إضافة واجهة وإسناد صلاحيات وacceptance tests قبل الادعاء بتوافرها. |
| إلغاء النشر من الواجهة | لا تظهر واجهة مباشرة موثقة لهذا السيناريو. | إضافة انتقال عمل مدعوم وحماية تدقيقية. |

## 6. خطوات النشر الفعلية

اتبع [دليل النشر](PRODUCTION_DEPLOYMENT.md): إعداد الأسرار، تثبيت قفل الاعتماديات، lint/build، migrations، إدخال كتالوج موثق، `production:preflight`، النشر خلف HTTPS، `production:smoke`، ثم اختبارات المستخدم والمدير الحقيقية. لا تتجاوز بوابة فاشلة ولا تستبدل خدمة حقيقية بمخزن local أو هوية اختبار.

## 7. الحسابات والأدوار المطلوبة

يلزم حساب قارئ حقيقي لاختبار التسجيل والقراءة والحفظ والتنزيل المسموح، وحساب إداري حقيقي لاختبار إدخال مرشح وحقوق وملف ونشر وسجل تدقيق. يمنح الدور من مستودع تفويض الخادم بعد تحقق Supabase، ولا يسمح عنوان البريد أو قيمة من المتصفح بمنحه. راجع [دليل المدير](ADMIN_GUIDE.md).

## 8. تعليمات المستخدم النهائي

يبحث المستخدم في المكتبة، ويفتح التفاصيل، ويبدأ القراءة في النسخة المتاحة، وينتقل بين الفصول. يحتاج تسجيل الدخول لحفظ التقدم واستئنافه، ويظهر التنزيل فقط حين تسمح حقوق النسخة والملف المنشور. راجع [دليل المستخدم](USER_GUIDE.md).

## 9. تعليمات مدير الموقع

ينشئ المدير سجلاً وصفياً أو يراجع مرشح إدخال موثق. لا ينشر إلا بعد نجاح مراحل metadata والحقوق والملف والمحتوى والفصول. يراجع readiness وسجل التدقيق والنسخ الاحتياطية، ولا يستخدم الحذف كبديل لإلغاء النشر. راجع [دليل المدير](ADMIN_GUIDE.md) و[دليل العمليات](OPERATIONS.md).
