# تقرير تنفيذ المرحلة P7 — موثوقية API والشبكة

## النتيجة التنفيذية

تم تنفيذ طبقة موثوقية موحدة لطلبات الشبكة في مشروع **Nexara**. تغطي الطبقة الجديدة مهلات صريحة، وإلغاءً متصلاً بإشارة المستخدم أو الطلب، وإعادة محاولة حتمية ومحدودة، وتصنيفاً أدق للأخطاء، وسجلات قابلة للمراجعة، والتحقق من استجابة JSON قبل وصولها إلى واجهة المستخدم. كما تم عزل موفري الاكتشاف الخارجيين، وإضافة cache مع stale-while-revalidate وقاطع دائرة، وتحويل بحث MongoDB من regex واسع إلى الفهرس النصي الموجود مع حد زمني للاستعلام.

> لا تُعرض رسالة تقنية من نوع “The operation was aborted due to timeout”. تُترجم المهلة الآن إلى خطأ API مصنف `timeout` برسالة واجهة واضحة، بينما يظهر الإلغاء المتعمد كـ`cancelled` ولا يعاد تلقائياً.

| المجال | تنفيذ P7 |
|---|---|
| طلبات واجهة API | `HttpClient` موحد يمنح كل طلب timeout و`AbortController` ومعرف طلب وسجل أحداث وتصنيف خطأ والتحقق من JSON. |
| سياسة retry | `GET` و`HEAD` فقط يعادان مرة واحدة افتراضياً عند الخطأ الشبكي أو `5xx` أو `429`؛ لا توجد عشوائية، والـbackoff حتمي. عمليات الكتابة لا تعاد تلقائياً. |
| الإلغاء | إلغاء المستخدم ينتج `cancelled` بلا retry؛ المهلة تنتج `timeout` مع retry محدود للقراءات فقط. |
| تنزيلات P6 | تنزيل Gutenberg وتنزيل الأصل المصرح يعبران الآن من النقل الموحد مع ميزانيات منفصلة وإشارة إلغاء. |
| الخادم | middleware جديد يولد أو يمرر `x-request-id`، ويوقف الطلب بعد 20 ثانية، ويربط مزود الخدمة بإشارة الطلب، ويحفظ سجل مدة/نتيجة. |
| مزودو الخدمة | بحث discovery يستخدم isolation، وإعادة محاولة حتمية واحدة، وcircuit breaker لكل مزود، وcache 20 ثانية مع SWR حتى 90 ثانية. |
| Gutenberg | موفر HTTP خارجي جديد لكتالوج Gutendex وOPDS والملف، بمهلات 8/8/15 ثانية، وretry حتمي وأخطاء `PROVIDER_ERROR` تتضمن المزود والمرحلة. |
| بحث MongoDB | يستخدم `$text` والفهرس `books_text_search` بدلاً من `$regex` عند وجود query، مع `maxTimeMS: 1500`. |

## سياسة الشبكة

| نوع العملية | ميزانية المهلة | retry | سبب القرار |
|---|---:|---:|---|
| API افتراضي | 10 ثوانٍ | قراءة فقط، محاولتان كحد أقصى | حماية عامة دون تكرار عمليات تغيير الحالة. |
| إتاحة تنزيل P6 | 8 ثوانٍ | محاولة إضافية واحدة | عملية قراءة خفيفة. |
| تفويض تنزيل P6 | 10 ثوانٍ | لا | يصدر تفويضاً وسجل تدقيق. |
| بث تنزيل داخلي | 20 ثانية | محاولة إضافية واحدة | تسليم ملف مصرح؛ لا يُعاد التفويض ذاته. |
| ملف signed خارجي | 30 ثانية | محاولة إضافية واحدة | يسمح بهامش نقل أعلى للملفات. |
| Gutendex/OPDS | 8 ثوانٍ | محاولة إضافية واحدة | بيانات تعريف خارجية مع fallback رسمي. |
| ملف Gutenberg | 15 ثانية | محاولة إضافية واحدة | حجم النقل أعلى والتحقق إلزامي. |
| request الخادم | 20 ثانية | غير منطبق | سقف يحمي workers والعميل من انتظار غير محدود. |
| بحث MongoDB | 1.5 ثانية | لا | الاستعلام المفهرس يفشل سريعاً بدل استهلاك قاعدة البيانات. |

## التغييرات الرئيسية

| الملف | التغيير |
|---|---|
| `src/api/http.ts` | النقل الموحد، تصنيف `timeout` و`cancelled` و`rate_limited` و`invalid_response`، سجل الشبكة، والتحقق من JSON. |
| `src/api/downloads.ts` | مسار تنزيل P6 الأصلي يستخدم النقل الموحد للروابط الداخلية والموقعة. |

| `tests/p7.api-network-reliability.test.ts` | بوابة قبول P7. |

## بوابة القبول P7

تمت إضافة الأمر التالي:

```bash
npm run test:p7
```

ويثبت الاختبار الحالات التالية:

| حالة البوابة | النتيجة |
|---|---|
| network latency | ناجح؛ طلب محدود الكمون ينجح ضمن ميزانيته. |
| slow provider | ناجح؛ تنتهي مهلة المزود ثم ينفذ retry حتمي واحد فقط. |
| provider failure | ناجح؛ بعد ثلاث طلبات فاشلة يفتح circuit breaker ويعزل المزود. |
| Mongo slow query | ناجح؛ يثبت الاختبار استخدام `$text` و`maxTimeMS: 1500` للبحث والعد. |
| aborted request | ناجح؛ يصنف كـ`cancelled` وليس timeout ولا تظهر رسالة abort التقنية. |
| concurrent request | ناجح؛ نتائج الاستعلامات المتوازية منفصلة ولا تتداخل. |
| repeated query | ناجح؛ الطلب الثاني يستخدم الـcache ولا يستدعي المزود ثانية. |

## ملاحظة تشغيلية

الفهرس النصي المحلي في MongoDB هو المسار الحالي لبحث الفهرس. عند انتقال المشروع إلى MongoDB Atlas ونمو بيانات الفهرس إلى مستوى يبرر ranking لغوي وتحليل عربي متقدم وautocomplete، يمكن إضافة **Atlas Search** كخيار بنية تحتية. لا يعتمد تنفيذ P7 الحالي عليه، وبالتالي لا يضيف تبعية مدفوعة أو إعداداً مخفياً؛ يستفيد مباشرة من `books_text_search` المنشأ فعلياً في المشروع.
